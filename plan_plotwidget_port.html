1. Context

PJ4 today has placeholder DockWidgets wrapped in a docking shell — there is no real plot canvas, no curve adapter, no drag-drop target, no zoom synchronization, no curve editor. The PJ4 plan (PJ4_PLAN.md §5.3, §8) specifies a wholesale lift of the PJ3 PlotWidget tree with one systematic rewrite: rebind PlotDataMapRef / TransformsMap reads to a DatastoreCurveAdapter over pj_datastore::DataReader and to pj_app_core services.

This plan ports the full PJ3 PlotWidget family and wires up the four demo features the user named: curve color assignment, drag-and-drop from the existing side panel, synchronized X-axis zoom across plots, and full plumbing into the new datastore.

In scope: the four demo features plus surrounding plumbing (tracker via PlaybackEngine, statistics dialog, plot-local display transforms — those are in PJ3 and PJ4_PLAN says lift them).
Out of scope: workspace-to-disk persistence, marketplace data-source UX changes, post-v1 features (PlotBackground colored zone, XY-plot tracker visualization).

2. User decisions guiding this plan

Data ingestion: the marketplace's CSV plugin (the user installs/uses it; we don't lift the PJ3 CSV plugin into the repo).
Link toggle: lives in MainWindow toolbar (global, PJ3-style).
Color picker: stock QColorDialog — no color_widgets vendoring this round.
Curve naming convention: topic/field/subfield (all slashes, ROS-style).

5. DatastoreCurveAdapter

5.1 Design — thin pull-through, no timeseries copy

The adapter is a read-only translator between QwtSeriesData<QPointF> and the datastore. It does NOT cache a vector of QPointF. sample(i) goes straight to a sealed PJ::TopicChunk on demand. The only state it owns is a small chunk index describing which sealed chunks overlap the visible window and how many rows each contributes — this lets sample(i) be O(log chunks).

This avoids three problems with caching a decimated array:

  • Zoom correctness. Qwt re-paints with whatever rect-of-interest is current; if we'd pre-decimated, zooming in would expose the staircase, not the underlying detail.
  • Decimation overlap. QwtPlotCurve's FilterPointsAggressive + ClipPolygons already do paint-time decimation. Adapter-side bucketing would either duplicate this work or hide raw extrema from Qwt before its filters can act.
  • Memory. A 100M-row topic stays in the datastore (chunked, with retention). The adapter never copies it.

API leverage — no plotjuggler_core changes needed

The design uses only existing public API of plotjuggler_core:

  • PJ::DataEngine::getTopicStorage(TopicId) → const TopicStorage*
  • PJ::TopicStorage::sealedChunks() → const std::deque<TopicChunk>& (commit-ordered, chunks never move)
  • PJ::TopicStorage::metadata() → TopicMetadata{time_range_min, time_range_max, total_row_count, ...}
  • PJ::TopicChunk::readTimestamp(row), ::readNumericAsDouble(col, row), ::isNull(col, row)
  • PJ::DataEngine::getTimeDomain(id) → const TimeDomain* for the display offset
  • PJ::DataEngine::commitChunks(...) returns changed TopicIds — the natural commit-notification primitive

The reactive signals (topicsCommitted, dataCleared, timeDomainChanged) live on our SessionManager in pj_app_core — a thin QObject wrapper around the engine. DataEngine stays signal-free by design (per plotjuggler_core/CLAUDE.md: Qt-optional substrate). No upstream API change required.

5.2 Header sketch

// pj_plot_widgets/include/pj_plot_widgets/DatastoreCurveAdapter.h
namespace PJ {

class DatastoreCurveAdapter final : public QwtSeriesData<QPointF> {
 public:
  DatastoreCurveAdapter(SessionManager* session, CurveDescriptor source);

  // QwtSeriesData<QPointF> overrides — pull-through, no copy.
  std::size_t size() const override;
  QPointF    sample(std::size_t index) const override;
  QRectF     boundingRect() const override;        // FULL-data bounds (not ROI). See §5.4.

  // Qwt calls this with the visible plot rect during updateScaleDiv.
  // NOT guaranteed to fire before boundingRect() — see §5.4.
  void setRectOfInterest(const QRectF& rect) override;

  // PJ3-equivalent helper: Y bounds restricted to a given X window.
  // Used by PlotWidgetBase for "vertical zoom-to-visible" (PJ3's getVisualizationRangeY).
  std::optional<std::pair<double, double>> visibleYRange(double x_min_sec, double x_max_sec) const;

  // Invalidation hooks (driven from SessionManager signals).
  void onTopicCommitted();              // append new chunks to chunk index, invalidate full bounds
  void onDataCleared();                 // wipe chunk index

  const CurveDescriptor& source() const { return source_; }
  std::optional<QPointF> sampleFromTime(double display_time_sec) const;

 private:
  struct ChunkSlot {
    const TopicChunk* chunk;          // borrowed; chunks in std::deque never move
    std::size_t row_start;            // first visible row WITHIN this chunk
    std::size_t row_end;              // one-past-last visible row WITHIN this chunk
    std::size_t cumulative_begin;     // global row index where this slot starts
    std::size_t cumulative_end;       // global row index where this slot ends (== next.cumulative_begin)
  };

  void ensureChunkIndex_() const;
  std::size_t findChunkSlot_(std::size_t global_row) const;  // last_slot_ → +1 → upper_bound
  QPointF readPoint_(const ChunkSlot& slot, std::size_t local_row) const;
  Timestamp displayOffsetNow_() const;                       // looks up live via DataEngine

  SessionManager* session_ = nullptr;
  CurveDescriptor source_;

  // Visible window — set by Qwt via setRectOfInterest. Defaults to ALL ROWS so size()/sample()
  // are valid before the first ROI arrives (Qwt may call boundingRect() first; see §5.4).
  Timestamp visible_t_min_raw_ns_ = std::numeric_limits<Timestamp>::min();
  Timestamp visible_t_max_raw_ns_ = std::numeric_limits<Timestamp>::max();

  // Last-slot cache — Qwt's QwtPointMapper iterates sample(i) sequentially.
  // Check current slot, then slot+1, then fall back to upper_bound.
  mutable std::size_t last_slot_ = 0;

  mutable std::vector<ChunkSlot> chunk_index_;
  mutable std::size_t total_visible_rows_ = 0;
  mutable bool chunk_index_dirty_ = true;

  // FULL-data bounds cache (X from metadata, Y from ColumnStats union across all chunks).
  // Invalidated only on topicsCommitted / dataCleared.
  mutable QRectF cached_full_bounding_rect_;
  mutable bool full_bounding_rect_valid_ = false;
};

}  // namespace PJ

5.3 Time conversion

display_ns = round(display_sec * 1e9)
raw_ns     = display_ns + display_offset_ns         // when querying datastore
display_x  = double(raw_ns - display_offset_ns) / 1e9  // when handing to Qwt

5.4 Read flow

Important Qwt-ordering invariant (verified by Codex against Qwt source): setRectOfInterest() is NOT guaranteed to fire before boundingRect(). Qwt's QwtPlot::replot() calls updateAxes() first; autoscale items hit boundingRect() there, and only afterwards does updateScaleDiv() propagate the rect to the series via setRectOfInterest. Therefore:

  • boundingRect() must return full-data bounds, never ROI-bounded — otherwise autoscale uses the previous frame's ROI and we get a one-frame lag bug on every replot.
  • size() and sample() must work before any setRectOfInterest arrives — hence the "all rows" default in the constructor.

setRectOfInterest(rect):

  1. Convert rect.left()/rect.right() from display seconds to raw nanoseconds: raw_ns = round(display_sec * 1e9) + displayOffsetNow_().
  2. If [t_min, t_max] changed, set chunk_index_dirty_ = true, reset last_slot_ = 0.
  3. Do NOT touch full_bounding_rect_valid_ — full bounds are independent of the ROI.

ensureChunkIndex_() (lazy, runs at most once per ROI change):

  1. const TopicStorage* ts = session_->dataEngine().getTopicStorage(source_.topic_id); — return early if null (topic deleted).
  2. Walk ts->sealedChunks(). For each chunk whose [time_min, time_max] overlaps [visible_t_min_raw_ns_, visible_t_max_raw_ns_]:
    • Binary-search the chunk's timestamp column for first row ≥ t_min and first row > t_max.
    • Boundary-guard rule: when narrowing, include one row before t_min and one row after t_max if available — otherwise line segments crossing the viewport boundary disappear before ClipPolygons can clip them (PJ3 had this behavior implicitly via full-array iteration).
    • Push {chunk, row_start, row_end, cumulative_begin, cumulative_end}.
  3. total_visible_rows_ = sum(row_end − row_start) across slots.
  4. Clear chunk_index_dirty_.

size(): ensureChunkIndex_(); return total_visible_rows_;

sample(i):

  1. ensureChunkIndex_();
  2. Last-slot cache — QwtPointMapper iterates sample(i) sequentially via for (int i = from; i <= to; i++):
    • If i falls inside chunk_index_[last_slot_], use it.
    • Else if i falls inside chunk_index_[last_slot_ + 1], advance and use.
    • Else std::upper_bound on cumulative_end; update last_slot_.
  3. local_row = slot.row_start + (i − slot.cumulative_begin);
  4. ts_ns = slot.chunk->readTimestamp(local_row);
  5. y = slot.chunk->isNull(col, local_row) ? NaN : slot.chunk->readNumericAsDouble(col, local_row);
  6. Return QPointF((ts_ns − displayOffsetNow_()) / 1e9, y).

boundingRect() — full-data bounds, NOT ROI-bounded:

  • X bounds from TopicStorage::metadata(): time_range_min/time_range_max, translated by display offset.
  • Y bounds from per-chunk stats: TopicChunk::stats.column_stats[col].min_value/max_value exists publicly via ChunkStats (verified in chunk.hpp). Take the union across all sealed chunks — no row walk required.
  • If a chunk's column_stats[col] entry has nullopt min/max (e.g. all-null column), skip it.
  • Cache in cached_full_bounding_rect_; invalidate only on topicsCommitted / dataCleared. Mouse pan/zoom does not invalidate.

visibleYRange(x_min, x_max) — for PJ3-style vertical zoom-to-fit:

This replaces PJ3's QwtSeriesWrapper::getVisualizationRangeY(range_X), which PlotWidgetBase uses for "zoom out vertical" semantics:

  • Walk chunk_index_ for chunks overlapping [x_min, x_max].
  • For chunks fully inside the X window: use chunk.stats.column_stats[col] directly (cheap, single lookup).
  • For partial-overlap chunks at the boundaries: scan only row_start..row_end in that chunk for min/max.
  • Return nullopt if no values are finite.

This is the only path that needs to scan rows for Y bounds; auto-zoom on full data does not.

5.5 Render decimation is Qwt's job

In PlotWidget, when each QwtPlotCurve is created, set Qwt's paint-attribute filtering flags: 

curve->setPaintAttribute(QwtPlotCurve::FilterPointsAggressive, true);
curve->setPaintAttribute(QwtPlotCurve::ClipPolygons,            true);

Qwt owns paint-time filtering and decimation. With these flags enabled, Qwt asks our adapter for samples within the ROI-narrowed visible row range and applies its own per-pixel collapse during paint. The adapter does not need to know pixel width and does not pre-decimate.

Caveat: Qwt still calls sample(i) for every candidate row in the visible range — paint-time filtering reduces the cost per pixel but not the call count. Performance therefore depends on cheap sample(i) (chunk-index + last-slot cache + raw chunk reads), which is why the design above optimizes that hot path.

5.6 Cache invalidation

The adapter listens for these signals from SessionManager:

  • topicsCommitted(QVector<TopicId> ids) — if source_.topic_id ∈ ids: append new chunks to chunk_index_ (or just mark dirty), invalidate bounding rect.
  • dataCleared() — clear chunk index.
  • timeDomainChanged(DatasetId id) — if source_.dataset_id == id: re-fetch display_offset_ns_; chunk index unchanged.

PlotWidget owns the connection (lambda capturing the adapter) and calls replot() after invalidation.

5.7 Multi-column mapping

One adapter per (TopicId, ColumnIndex) — i.e. one curve per leaf scalar. Structured topics fan out into multiple curves named topic/field/subfield.

5.8 PointSeriesXY — separate class with its own alignment index

Do NOT compose XY plots out of two ROI-driven DatastoreCurveAdapters. For a time-series adapter, Qwt's ROI QRectF.x() is display time. For an XY plot, Qwt's ROI QRectF.x() is the X curve's numeric value. Forwarding the same QRectF into two time-series adapters would narrow on the wrong domain.

Instead, PointSeriesXY is its own QwtSeriesData<QPointF> subclass that builds a lazy alignment index over the raw datastore: 

class PointSeriesXY final : public QwtSeriesData<QPointF> {
 public:
  PointSeriesXY(SessionManager* session, CurveDescriptor x_src, CurveDescriptor y_src);

  std::size_t size() const override;
  QPointF    sample(std::size_t i) const override;
  QRectF     boundingRect() const override;       // full-data XY bounds from ColumnStats
  void       setRectOfInterest(const QRectF&) override;  // narrows by X-VALUE, not time

  void       onTopicCommitted();   // invalidate alignment index
  void       onDataCleared();
};

Alignment-index build (lazy, rebuilt on commit/clear):

  • Same-topic fast path: if x_src.topic_id == y_src.topic_id, X and Y are different columns of the same chunk; pair by row index — no scan needed.
  • Different-topic path: two-pointer scan over both topics' sealedChunks() by raw Timestamp; emit a PairSlot{x_chunk, x_row, y_chunk, y_row} entry only on exact timestamp match. Mismatched samples are dropped (PJ3 behavior).

sample(i): dereference pair_index_[i], read both values fresh from the chunks, return QPointF(x_value, y_value). No timestamp matching at sample time.

This preserves the "no copy of timeseries data" principle — the index stores chunk/row references, not values.

6. Drag-drop wiring

  • Drop target: the Qwt plot canvas (forwarded through PlotWidgetBase via Qt's drag-event signals). Not DockWidget — matches PJ3 and aligns with where the user visually expects to drop.
  • MIME formats (no change): curveslist/add_curve, curveslist/new_XY_axis — already emitted by the existing CurveTreeView.
  • Decode: payload is a QDataStream of QString curve names, identical to PJ3.
  • add_curve path: for each name, look up CatalogModel::curveDescriptor(name). If found, create a DatastoreCurveAdapter, wrap it in a QwtPlotCurve, assign next color from the cycle, attach to plot. Reject silently with a status-bar toast if the name is no longer in the catalog.
  • new_XY_axis path: requires exactly two curve names. Construct a PointSeriesXY from two adapters (timestamp-aligned by exact match for v1). The plot enters XY mode (isXYPlot() == true). Drops on a non-empty plot are rejected, matching PJ3.

8. Synchronized zoom

8.1 Owner: MainWindow (matches PJ3)

MainWindow.ui gets QToolButton buttonLink (checkable, object name preserved). State persisted to QSettings under PJ3 key MainWindow.buttonLink.

8.2 Plot-side signal

PlotWidget emits void rectChanged(PlotWidget* modified_plot, QRectF new_range);

Emitted on user-driven zoom/pan/magnify and from setZoomRectangle(rect, /*emit=*/true).

NOT emitted on setZoomRectangle(rect, /*emit=*/false) — this is the broadcast version, called by MainWindow's broadcast loop. Suppressing emit prevents the echo loop. Also not emitted for XY plots.

8.3 Wiring

// MainWindow ctor
connect(ui->tabbedPlotWidget, &TabbedPlotWidget::tabAdded,
        this, &MainWindow::onPlotTabAdded);
// on existing tabs at startup, call onPlotTabAdded for each

// onPlotTabAdded(PlotDocker* docker)
connect(docker, &PlotDocker::plotWidgetAdded,
        this, &MainWindow::onPlotAdded);

// onPlotAdded(PlotWidget* plot)
connect(plot, &PlotWidget::rectChanged,
        this, &MainWindow::onPlotZoomChanged);
connect(plot, &PlotWidget::trackerMoved,
        this, &MainWindow::onTrackerMoved);
connect(plot, &PlotWidget::curvesDropped, ui->curveListPanel,
        &CurveListPanel::clearSelections);

8.4 Broadcast algorithm

void MainWindow::onPlotZoomChanged(PlotWidget* src, QRectF new_range) {
  if (!ui->buttonLink->isChecked()) return;
  for (auto* plot : allPlotsInAllTabs()) {
    if (plot == src) continue;
    if (plot->isEmpty()) continue;
    if (plot->isXYPlot()) continue;
    if (!plot->isZoomLinkEnabled()) continue;  // per-plot opt-out (always true for v1)
    QRectF rect = plot->currentBoundingRect();
    rect.setLeft(new_range.left());
    rect.setRight(new_range.right());
    plot->setZoomRectangle(rect, /*emit=*/false);
    plot->replot();
  }
}

X-axis is synced; each plot keeps its own Y range. PJ3 calls on_zoomOutVertical_triggered(false) after broadcast to reset Y to data extent — port that behavior intact.

9. Tracker integration

  • PlotWidget owns its CurveTracker. DockWidget::onTrackerTime(double t) forwards to plot_widget_->setTrackerPosition(t).
  • MainWindow connects PlaybackEngine::currentTimeChanged → broadcast onTrackerTime to every dock (walk the tab/dock tree once per signal).
  • User-driven tracker drag in a plot emits PlotWidget::trackerMoved(QPointF p); MainWindow::onTrackerMoved calls session_->playbackEngine().setCurrentTime(p.x()). The broadcast then echoes back to all plots, including the source.
  • XY plots don't show a time-tracker line in v1.

10. pj_app_core service additions

10.1 SessionManager — minimal v1 surface

Owns a PJ::DataEngine directly. Three things only:

PJ::DataEngine& dataEngine();
PJ::DataReader  createReader() const;       // thin wrapper for adapter convenience

// Q_SIGNALS
void topicsCommitted(QVector<PJ::TopicId> ids);  // emitted explicitly after engine.commitChunks()

That's the minimum the four demo features need. The sole reason this class exists rather than holding DataEngine directly: DataEngine has no Q_SIGNALS by design (Qt-optional substrate per plotjuggler_core/CLAUDE.md) — something must bridge that gap, and this is it.

Explicitly NOT in v1:

  • displayOffsetForTopic(TopicId) — the adapter calls engine.getTimeDomain(id) directly. No reason for a wrapper.
  • dataCleared() Q_SIGNAL — no consumer. Add when something asks.
  • timeDomainChanged(DatasetId) Q_SIGNAL — no consumer. Add when something asks.

The CSV plugin (out of scope) drives engine.commitChunks(); a thin shim emits topicsCommitted after that returns. That's the only integration point.

10.2 CatalogModel — minimal v1 surface

Existing API stays (curveNames(), curveAdded, curveRemoved, cleared) — CurveListPanel already wires to it.

One method added for drag-drop name resolution:

std::optional<CurveDescriptor> curveDescriptor(const QString& name) const;
void rebuildFromDatastore();  // initial population on session start, on topicsCommitted

Build: enumerate topics via DataReader::listTopics, walk each topic's TypeTreeNode for numeric leaves (Float32/Float64/Int32/Int64/Uint64/Bool — string columns excluded for v1), assemble topic/field/subfield names, store name→CurveDescriptor in a tsl::robin_map. On topicsCommitted, incremental update.

Explicitly NOT in v1: curves() → QVector<CurveDescriptor> bulk getter (no consumer). Iteration goes through curveNames() + per-name lookup, which is what the side panel already does.

10.3 Why not collapse SessionManager + CatalogModel?

They have genuinely different consumers — the adapter wants DataReader, the side panel wants name enumeration. Splitting is natural. If both classes turn out < 50 LOC each in practice, revisit at the end of M1; otherwise leave them split.

10.4 Why not skip the service layer entirely?

Two non-trivial reasons:

  • Widget-family siblings rule (PJ4_PLAN.md §0): plot, 2D, and 3D widget libraries cannot depend on each other and must not depend on pj_app. They share state through pj_app_core services. If we kill SessionManager and PlaybackEngine, every widget gains a transitive dependency on MainWindow.
  • Qt-optional substrate: plotjuggler_core is built without Qt by default. DataEngine can't carry Q_SIGNALS itself; the bridging layer has to live in pj_app_core.

So the abstraction is load-bearing, not ceremonial.

10.5 What's NOT added in this round

WidgetRegistry, TransformRegistry, WorkspaceManager, UndoManager, ToolboxManager, NotificationCenter — none required for the four demo features. Adding them prematurely couples the plot port to scaffolding with no consumer yet.

14. Risks & open items

color_widgets removed from scope simplifies the build but loses the color-wheel polish. If the user later wants the full PJ3 dialog, we'll vendor + Qt6-patch in a follow-up.
CSV plugin from marketplace must commit through DataEngine and trigger SessionManager::topicsCommitted — the plugin is out of scope for this plan, but it's the integration point. If the marketplace plugin doesn't emit anything, we'll need a thin shim (verify during M3).
field_path vs column_index ambiguity: this round uses column_index for fast access and stores field_path alongside as a stability fallback. If schema evolution lands before this port stabilizes, the descriptor lookup may need to re-resolve via field_path.
Render decimation depends on Qwt's FilterPointsAggressive being effective at the row counts we hand it. If a topic exposes 10M+ visible rows and Qwt's filter is too slow per sample(i) call, we'd revisit by adding a coarser setRectOfInterest stride (still no pre-decimation in the adapter — narrowing the visible row range only). Verify at M2/M3 with a large CSV.
Threading & chunk lifetime. The adapter holds raw const TopicChunk* into std::deque. Deque appends preserve existing references (good), but TopicStorage::clearChunks() and DataEngine::enforceRetention() invalidate them. DataEngine has no visible locking. v1 must guarantee no engine mutation during Qwt paint — easiest path: SessionManager serializes commits / clear / retention onto the GUI thread (or uses Qt::QueuedConnection for the bridge signals so they fire between paints, never during).
Retention has no signal. DataEngine::enforceRetention() returns void. If v1 ever calls it, SessionManager must wrap and emit a topic-data-changed signal so adapters rebuild their chunk index. v1 demo doesn't enforce retention, but flag this for the streaming-source phase.
Display-offset must be looked up live via DataEngine::getTimeDomain(id), not cached on the adapter. timeDomainChanged signal (deferred for v1) would otherwise cause stale-offset bugs. v1 reads the offset on each setRectOfInterest; if the demo adds a domain-change UI, add the signal.
Echo-loop avoidance depends on setZoomRectangle(rect, false) not emitting rectChanged. Test this explicitly in M5 — a missed connection here causes infinite recursion.
Workspace-to-disk persistence is not part of this round. xmlSaveState/xmlLoadState work in memory; saving/loading layout files is a future workspace-manager milestone.
Tracker on XY plots is deferred. PJ3 had a partial implementation; v1 of PJ4 simply hides the tracker on XY plots.
Drag-drop payload byte-compat verified. PJ4 CurveTreeView.cpp:147-159 writes QDataStream << name per QString with MIME "curveslist/add_curve" / "curveslist/new_XY_axis"; PJ3 plotwidget.cpp:471-512 reads the same way. Both ends are Qt6, so QDataStream default version matches. No protocol fix required.

Concrete consequences for this port:

  • DatastoreCurveAdapter's chunk index uses std::vector<ChunkSlot> (stable while we hold it) but the underlying TopicStorage::sealedChunks() is a std::deque — chunks never move, slot pointers stay valid.
  • CatalogModel's name-to-descriptor map uses tsl::robin_map<QString, CurveDescriptor>.
  • Adapter sample(i) must handle "topic deleted mid-paint" by returning QPointF(NaN, NaN) — Qwt breaks the curve. getTopicStorage(id) returning nullptr is the trigger.
  • SessionManager::createReader() returns by value (small RAII view, copyable), not PJ::Expected; the construction is infallible.
  • Time arithmetic in the adapter stays in PJ::Timestamp (ns) until the final display_x_sec conversion. Don't drop to double seconds early — precision loss accumulates.

16. Execution model

Per CLAUDE.md: each milestone is delegated to Codex with a milestone-scoped brief. Claude runs the two-reviewer pre-commit gate (simplicity reviewer + bug reviewer in parallel) over the produced diff, addresses every real finding, surfaces the diff + review summary to the user, and only commits after explicit user confirmation.

This document is the merger of two parallel plans (Claude + Codex). Codex contributed the CurveDescriptor first-class type, explicit display-offset math, and echo-loop prevention as a named invariant. Claude contributed surfacing gating user decisions up front (data source via marketplace CSV, stock QColorDialog, topic/field/subfield naming) and trimming the service surface to only what consumers need.

After user review, the adapter design was reworked from "cache + min/max bucket downsampler" to a thin pull-through over QwtSeriesData::setRectOfInterest + Qwt paint-time filtering — render decimation is Qwt's job. Codex's resumed second-pass review (against the corrected design) caught: setRectOfInterest ordering vs boundingRect (full-data bounds required, ROI-based bounds would lag a frame); ChunkStats::column_stats exists publicly (no walk needed for Y bounds, no upstream API extension); the last-slot cache for sequential sample(i); the boundary-guard rule; and a separate PointSeriesXY with its own alignment index (forwarding ROI to two time-series adapters narrows by the wrong domain). Threading/lifetime around std::deque chunk references is now a documented invariant.

No plotjuggler_core/ API extensions are needed for v1.
