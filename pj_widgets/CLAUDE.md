# pj_widgets

## Purpose

Reusable Qt widgets and UI helpers — the kind of controls that could be dropped into another Qt application without dragging PJ4-specific state with them. Static library, `Qt6::Core` / `Gui` / `Network` / `Svg` / `Widgets` only.

## Hard constraints (from root CLAUDE.md)

- Depends only on **Qt and the C++ standard library** (plus the dependency-free, header-only `raster_ipc/` wire-protocol contract, which is not a PJ module).
- **No dependencies on `pj_runtime`, `pj_app`, or any other PJ module.** Anything that needs runtime state belongs upstream of here.
- If a widget is specific to PlotJuggler workflows (e.g. plot-specific dockers), it belongs in the widget-family module instead.

## Inventory

Widgets:

| Header | Role |
|---|---|
| `Dialog.h` + `Dialog.ui` | Chrome wrapper used by app dialogs and `FileDialog`. |
| `FileDialog.h` | `QFileDialog` wrapped in `PJ::Dialog` chrome. |
| `MessageBox.h` | Themed `QMessageBox` replacement — frameless modal with heading, body, optional "Don't show again" checkbox, and a vertical column of N labelled buttons (primary button paints the light_purple → light_blue gradient via the `msgbox_role` dynamic property; over-long labels word-wrap onto multiple lines instead of clipping). Static helpers: `information` / `warning` / `critical` (single OK) + `question` (multi-button, returns clicked index). |
| `ProgressBar.h` | App-styled `QProgressBar` variant — rounded thick-outlined trough, light-blue rounded fill, single-colour centred caption (`setFormat("Loading MCAP")`). Logic-free; the look comes entirely from the `PJ--ProgressBar` QSS class rule (so a plain `QProgressBar` keeps the default look). `Q_OBJECT` is mandatory — it's what makes the class selector match. |
| `ProgressDialog.h` | `QProgressDialog` replacement on the `Dialog` chrome: message + bar + up to two stop buttons. Domain-neutral — reports `Action::Primary` / `Action::Secondary` (sticky, polled via `action()` or the `stopRequested` signal) and leaves their meaning to the caller. No close affordance (base ✕ hidden, Esc swallowed). |
| `RecentFilesMenu.h` | `QMenu` populated from a persistent recent-files list. |
| `ComboBox.h` | `QComboBox` subclass that auto-installs `ComboBoxGradientDelegate` so the popup paints the app gradient. **Use this instead of plain `QComboBox` everywhere in PJ4** (promote `QComboBox` → `PJ::ComboBox` in `.ui` files). |
| `ComboBoxGradientDelegate.h` | Item delegate painting the light_purple → light_blue gradient on selected/hovered rows; works around the QSS limitation that combobox popups ignore gradient `::item:selected` rules. |
| `ColorPickerPopup.h` | Compact popup color picker. |
| `ColorPickerWidget.h` | Standard fixed-size colour swatch button that opens a `ColorPickerPopup`; the one reusable replacement for the per-layer swatch buttons each module used to hand-roll. `colorChanged()` fires only on user picks; `setColor()` is silent. |
| `CheckButton.h` | Checkable "pill" toggle button — the label sits inside an accent-filled (checked) / accent-outlined (unchecked) capsule. A labelled, click-the-whole-control alternative to `QCheckBox`; distinct from `ToggleSwitch` (a sliding switch with no inline text). |
| `ToggleSwitch.h` | iOS-style sliding-switch toggle replacement for `QCheckBox`. |
| `ToastManager.h` / `ToastNotification.h` | Transient bottom-right "toast" notifications over a host widget. `ToastManager` owns a transparent container (sized to the host — forward the host's `resizeEvent` to `updatePosition()`) and stacks `ToastNotification` frames, newest at the bottom; each slides in from the right and auto-dismisses after a timeout (or on ✕). The message is **rich text with external links enabled**, so an `<a href>` opens in the browser with no extra wiring. Styled via the `PJ--ToastNotification` QSS rule; child `objectName`s (`toastIcon`/`toastMessage`/`toastCloseButton`/`toastManagerContainer`) are preserved from PJ3 for stylesheet selectors. |
| `IntScrubber.h` / `DoubleScrubber.h` / `ScrubberBase.h` | Drag-to-scrub numeric inputs. |
| `Search.h` | The **one canonical search/filter input** across PJ4: a non-interactive, self-retinting magnifying glass butted flush against a borderless `QLineEdit`, both sharing a single flat background (`WA_StyledBackground`, `PJ--Search` QSS rule) so they read as one control. A trailing themed clear "×" shows only while the field holds text. `setPlaceholder` (default `"Filter..."`), `text()`/`setText()`/`clear()`, `textChanged`/`returnPressed` signals, `lineEdit()` for advanced wiring, `setFieldObjectName()` to stamp the inner field for dialog-host binding. Height tracks the icon-size chrome metric via `setChromeMetrics()`. Two background tones via `setVariant()`: `kBanner` (default, `banner_input` tone, for header-band filters) and `kStandalone` (`input` tone, for a filter on its own surface — e.g. the marketplace, keyed by the `variant` dynamic property). Bakes in the "sibling glyph, not a `QLineEdit` leading action" workaround (Qt hardcodes an in-field icon to 16 px on short fields). Replaces the four hand-rolled filter variants (Datasets / Custom Series / Curves / marketplace). Promote `QLineEdit` search fields → `PJ::Search` in `.ui` files. |
| `SectionHeaderBand.h` | Canonical `ChromeMetrics::bandHeight()` titlebar-tone section header strip (leading indent baked in); background themed once via the `PJ--SectionHeaderBand` QSS class rule, so instances need no per-objectName stylesheet registration. Optional inline **filter banner**: set `filterPlaceholder` (+ `filterFieldName` for host binding) to grow a trailing canonical `Search` control (glyph + flat field), reusable from plugin `.ui` files; access it via `filterSearch()` or its line edit via `filterEdit()`. |
| `SvgButton.h` | `QToolButton` showing a themed SVG icon that **re-tints itself on a theme switch** (via `changeEvent` on `ApplicationPaletteChange`/`StyleChange` — Qt 6 has no `QApplication::paletteChanged`), with **no per-button host wiring**. Replaces the repeated "QToolButton + autoRaise + NoFocus + setFixedSize + setIconSize + loadSvg + retint-on-stylesheetChanged" pattern (which several sites forgot, leaving icons stale). Two size presets via `Size::kDefault` (24x24) / `kSmaller` (20x20); `setExtent(button_px, icon_px)` for chrome-metrics-driven buttons (button = icon_size + icon_padding). `setIconPath()` swaps the glyph for state-dependent toggles and keeps re-tinting it. `autoRaise`+`NoFocus` by default; checkable via `QToolButton::setCheckable`. Uses `loadSvg`'s 64-px cache, so best for small chrome icons — large icons (e.g. the 48-px placeholder glyphs) still want `renderSvgPixmap` for crispness. |
| `LayerListView.h` | Reorderable list of `LayerRow` items (id / name / visibility / warning state) with drag-reorder; the reusable scene-layer list control. |
| `RangeSlider.h` | Two-handle (min/max) slider for selecting a sub-range. |
| `ConfigPanelHost.h` | Single-slot container that hosts one config panel at a time, taking ownership and `deleteLater()`-ing the previous one. |
| `CredentialsEditor.h` | Composite credentials editor (cert path / api key / allow-insecure) used as the host-side widget for plugin `.ui` `<widget class="CredentialsEditor">`; domain-neutral, with optional plugin-supplied `apiKeyPattern`. |
| `DateRangePicker.h` | Date/time range picker bundle (`CalendarWidget` / `TimePickerWidget` / `RangeCalendarWidget` / `DateRangePicker`); registered by class name for plugin `.ui` files. Emits `filterChanged(RangeFilter)`. |
| `RealSlider.h` | Floating-point `QSlider`. |
| `FlowLayout.h` | Standard Qt example flow layout. |
| `ElidingLabel.h` | `QLabel` that elides instead of clipping. |
| `CurveTreeView.h` | Tree view tuned for PlotJuggler's curve catalog (no runtime coupling — model is plugged in by the caller). Carries the demand-subscription row states as caller-driven decorations: dimming for placeholders/unsubscribed topics (`CurvePath::is_placeholder`/`is_unsubscribed` + `setUnsubscribedKeys`), accent-blue names for force-streamed topics (`setForcedTopicPaths`, marks retained across rebuilds), a one-shot auto-expand armed for a placeholder that later promotes to fields (`requestExpansionWhenPromoted`), and the `placeholderPeekRequested` double-click signal the host maps to a bounded field-discovery subscription. The host resolves rows back to catalog items via `catalogKeyOf`/`catalogKeysUnder` (a promoted scalar topic's group row carries no key — its keys live on the field leaves). Also filters by topic kind (`setVisibleCurveKinds` — a topic's 2D/3D scene marker governs its whole subtree; Plot is the by-exclusion bucket) and, when a dataset's topics are all filtered out, keeps the dataset name and shows a caller-supplied message as a muted child row (`setEmptyFilterMessage`). |
| `VisualizationPlaceholderWidget.h` | Placeholder shown when no data widget is bound. The Plot / 2D / 3D icons are clickable: a click emits `visualizationRequested(VisualizationKind)` so the host converts the dock into an empty widget of that family (a catalog drop still creates-and-populates directly). |
| `RasterStreamView.h` | Hosts an external renderer process and paints its framebuffer (streamed over shared memory via the `raster_ipc/` contract) in a panel; forwards key input through an injectable translator. Pure Qt, no window embedding. |
| `RasterFrame.h` | Decodes a `raster_ipc` shared-memory frame into a `QImage` (consumer side of the protocol). |
| `Scrollbar.h` | Overlay "scroll pill" (`PJ::Scrollbar`) for a `QAbstractScrollArea`. Forces the matching native bar to `AlwaysOff` (the bar stays live as the scroll-state source of truth) and paints a thin floating pill that mirrors its handle. Reveals on hover over the edge strip and on wheel/trackpad scroll (auto-hides after a hold), and **drags to scroll when the handle is grabbed** (presses off the handle fall through to the underlying view, so content clicks are never stolen). One instance per axis. Theme-aware color via `scrollbar_detail::defaultAccent()` keyed on `QPalette::Window` lightness (info-blue on light, pale-grey on dark); override with `setAccentColor`. `setAutoHide`/`setFadeDurationMs`/`setInteractive`/`setClickToScroll` configure it (the last opts a viewport-owning host like the Timeline into full-strip click-to-scroll; default is handle-only so an overlay never steals content clicks). Used by `Timeline` and attached to plugin scroll areas by `pj_dialog_host`'s `adaptScrollAreas` (which skips an axis a plugin pinned to `AlwaysOn`). |
| `Timeline.h` | Reusable multi-track Source Timeline: each loaded source is a draggable bar editing only its own per-source display offset (`display = raw − offset`); an **Align** button snaps all displayed starts to the earliest. Two classes in one `.h`/`.cpp` pair: `TimelineScene` (a genuinely Qt-free timing/geometry/alignment math class — `displayWindow`/`sceneExtent`/`ns↔px`/`barSpan`/`zoom`/`ruler`/`alignStartsToCommonOrigin`/`alignCentersToCommonOrigin`/`alignEndsToCommonOrigin`/`snapToEdges`, plain `qint64`/`double` types) and `Timeline` (the `QWidget`/`QGraphicsView` view). Runtime-agnostic — plain-typed slots (`setTracks`/`setPlayhead`/`setReferenceLine`/`setDisplayRange`) and intent signals (`offsetChangeRequested`/`alignRequested`/`playheadSeeked`/`referenceLineMoved`); the host (`pj_app`'s `SourceTimelineController` for runtime state, `MainWindow` for the reference toggle) does all conversion. Dark Blender-style strip: compact ruler with frame numbers at the top, faint full-height tick gridlines, a diagonal hatch over the empty (non-data) span, and a light-blue tint over the data (OR) span. Two draggable marker needles (one `TimelineNeedleItem` type): the pink **playhead** and the blue **reference line** (shown when the host toggles it on); each darkens + shows a ruler-aligned timestamp pill while grabbed. Ruler ticks and the grabbed-needle pills relabel between **elapsed time** (relative to the ruler epoch — `0:00`, `0:10`, `1.5s`) and the **absolute Unix timestamp in seconds** via `setAbsoluteTimeLabels` (the host drives it from its "use time offset" toggle); this is pure relabelling — bar/needle positions never move. The playhead/range/reference setters take the host's external (playback) frame; `setTimeFrameOffsetNs` supplies the ns gap to the bars' internal frame, which the setters **add** and the seek signals **subtract** in integer ns — so the needle stays bit-exact with the playback cursor even at epoch scale (adding that offset in `double` seconds would round to ~240 ns and desync the two readouts). Navigation: the wheel zooms horizontally (cursor-anchored — the instant under the pointer stays put), a left-drag on empty background pans (a plain background click deselects); the scene keeps a sticky ±1 min buffer so small edge drags don't resize it. A left **name column** lists each track's dataset name, pinned and row-aligned with its bar so the name stays visible when the bar scrolls off horizontally or squashes thin; its right edge is a draggable splitter that resizes the column, and dragging a name row reorders the tracks (`tracksReordered`). Name rows are **multi-selectable** (plain click selects one, Ctrl/Meta+click toggles, Shift+click extends a range), highlighting both the row and its bar; when **≥2 sources are selected** the header's **merge button** enables and emits `mergeRequested` on click (the host confirms + performs the destructive dataset merge); it counts only filter-visible selected sources. Its top band is a **"Datasets" header** (titlebar tone, 2-px-indent title; `timelineDatasetsHeader`/`timelineDatasetsLabel`) hosting the label-less merge button (`timelineMergeButton`, an `SvgButton` with the merge icon, 24-px, self-retinting) on the right — disabled until ≥2 sources are selected. A programmatic dataset filter remains (`setDatasetFilter`, case-insensitive substring; filtering never resets the view/zoom) but has no built-in header UI. The align/reset actions live solely on the app's align rail — there is no kebab menu on the header. Dragging a bar edge-snaps to a neighbour's start/end (orange guide line; `setSnapEnabled`, toggled by the align rail's "snap to" button; drag past the threshold to release). The app's align rail (RHS, `pj_app`) hosts the align-left/center/right + snap-toggle icons at the top and a "reset all" button at the bottom. Both native scrollbars are replaced by canonical `PJ::Scrollbar` overlay **pills** (theme-aware: info-blue on light, pale-grey on dark) — horizontal on the bottom strip, vertical on the right strip — that mirror their scrollbar handles, reveal on hover or scroll, and scroll the view when their handle is dragged. The ruler number line is **sticky**: vertical scrolling moves the rows underneath it while the ruler (and the needles' time pills) stay pinned to the viewport top (`syncStickyHeader`), so the numbers never scroll away with the rows. View-state accessors let the host save/restore the timeline into a layout: `zoom()`/`setZoom`, `viewportLeftDisplayNs()`/`setViewportLeftDisplayNs` (the scroll position, expressed in data-ns so it survives a zoom change), and `nameColumnWidth()`/`resizeNameColumn` (resize the column without disturbing the host-pinned floor); `nameColumnWidthChanged` reports a user separator drag so the host can keep that width sticky. **Auto-zoom** (`setAutoZoomEnabled`/`isAutoZoomEnabled`, default on): on new data (or `fitToContents()`, which the host calls after an alignment) the view zooms so the largest extent — the union of all bars — fills it; an empty timeline always fits the playback range regardless. The app persists the toggle in QSettings and exposes it in Preferences → Plotting. |

Helpers (header-only or small):

| Header | Role |
|---|---|
| `ChromeMetrics.h` | Shared icon/layout spacing constants for dialog chrome, broadcast from MainWindow. Defaults `{icon_size=24, icon_padding=4, layout_padding=2, layout_spacing=2}` — matching MainWindow's first-launch baseline so a dialog constructed before the live broadcast (or one that never receives it) still shows the canonical `titleBarHeight()`. |
| `Hatch.h` | The single app-wide "no data" diagonal hatch: `kHatchSpacing`, `appHatchColor()` (theme ink from `QGuiApplication::palette()`), and `drawHatch(painter, rect, global_origin, color)`. Phasing every caller to the same global grid (`X+Y ≡ 0 mod spacing`, via `global_origin = widget->mapToGlobal({0,0})`) makes all hatches **continuous** — windows into one shared layer, not just same-spacing. Used by `Timeline` (empty span) and `RangeSlider` (unselected track). |
| `Colormap.h` | Shared scientific colormaps (turbo/viridis/plasma/grayscale): the `Colormap` enum, `colorFor()`, `buildColormapLut()` (a CPU RGBA8 LUT for LUT-sampling GPU backends — the 2D depth shader) and `colormapGlsl()` (the *same* polynomials as GLSL, injected into in-shader backends — the 3D pointcloud pass). One source of truth so a scalar maps to the same colour in the 2D and 3D views. Qt-free / no `pj_base` (returns a plain `ColormapRgb`, not `sdk::ColorRGBA`). |
| `FrameworkTokens.h` | Typed C++ reader over the semantic UI framework palette (`resources/ui_framework.md`). Covers colors — `Surface`, `Variant`x`State` fills + `special()`, foreground ink (`onSurface`/`onFill`/`onSpecial`/`text`/`iconInk`), `outline()` (stateful stroke incl. focus), `overlay()` (alpha state-layers/scrim/hud), selection (`selectionFill`/`onSelection`), `elevatedSurface()`, `gradient()` — **and non-color axes** `space()`/`metric()`/`radius()`/`stroke()`/`duration()`/`type()`. The 4 interaction variants are accent families named by emphasis: **Neutral** (grey), **Accent** (blue), **Highlight** (magenta), **Emphasis** (yellow). The **QSS palette in `stylesheet_{dark,light}.qss` is the single ground truth**; this header holds no values — each call parses (and caches) the compiled stylesheet resource for the requested theme. Self-painted (QPainter) widgets use it because they can't reach the QSS `${token}` engine. `framework_tokens_test` asserts every role resolves in both themes. Beyond the base grid it also exposes the extended semantic families — `status()`, `destructive()`, `progress()`, `sliderHandle()`/`scrollHandleHovered()`, `syntaxInk()`, `contrastInk()`, `diagnostic()`, `onOverlayHud()`, `onCodeEditor()`, `iconInkMuted()` — so **every** colour in the app resolves from the framework palette (the legacy brand tokens and the old `ThemeColors.h` mirror have been retired). |
| `Style.h` | Common style accessors. |
| `SvgUtil.h` | Helpers to load and recolor SVG resources. |
| `VisualizationKind.h` | Neutral `enum class VisualizationKind { Plot, Scene2D, Scene3D }` — the UI vocabulary `VisualizationPlaceholderWidget` emits; the app shell maps the scene families to concrete `"scene2d"`/`"scene3d"` object-widget kinds. |

## UI convention

Per root CLAUDE.md: **prefer `.ui` files**. `AUTOUIC` is on. Search path is `src/`. The only `.ui` today is `Dialog.ui` — keep new chromed dialogs on the same pattern.

## Tests

`tests/` holds a focused gtest binary per widget whose behavior is non-trivial (e.g. `curve_tree_view_test.cpp`, `messagebox_test.cpp`, `progress_bar_test.cpp`, `credentials_editor_test.cpp`, `layer_list_view_test.cpp`, `colormap_test.cpp`, `scrubber_base_test.cpp`, `file_dialog_test.cpp`, the raster IPC pair). Keep adding one per non-trivial widget.

`pj_widgets` has no `docs/` folder — each widget's intent fits in its header doc-comment.
